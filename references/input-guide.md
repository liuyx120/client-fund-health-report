# 输入信息与 JSON 规范

## 用户需要提供什么

### 必需信息

1. **客户持仓及截止日**
   - 数据截止日
   - 基金代码、基金全称、A/C 等份额类别
   - 当前持仓市值
   - 投入本金或累计成本
   - 持有收益率或盈亏金额（至少提供其中一项；其余可计算）
2. **可选产品池**
   - 可转换或可新建仓产品全称、代码和份额
   - 销售档期或当前开放状态
   - 产品类型、风险等级、持有期或封闭期
3. **本次调整边界**
   - 是否允许赎回、转换、加仓、新建仓
   - 可使用的新增资金；没有则明确写“无新增资金”
   - 最多调出、调入或新增多少只产品
   - 必须保留、禁止新增或优先考虑的产品

### 建议提供

- 期望年化收益与可承受回撤
- 预计持有期及未来用款安排
- 风险等级、投资经验和流动性要求
- 每只持仓的份额、净值、申购日、已赎回和已实现收益
- 渠道费率、转换规则、最低申购额和赎回到账日
- 报告日期、客户称谓、是否匿名、目标页数

## 缺失信息的默认处理

- 未给收益或回撤目标：以改善集中度、重叠度、流动性与持有体验为主，不虚构数值目标。
- 未给预计持有期：不优先配置带最短持有期或封闭期产品；如有明显适配价值，仅列条件候选并提醒确认期限。
- 未给新增资金：按无新增资金处理，不假定客户可以加钱。
- 未给现金要求：根据账户规模、集中度、销售窗口和流动性决定是否留现金，不固定保留。
- 未给销售状态：产品只列“待渠道确认”，不得写成确定可买。
- 未给最大调仓数量：以减少无效小额交易为原则，优先解决一至三个最重要问题。
- 图片信息无法辨认：先说明具体字段，不自行猜测代码、金额或正负号。

## 结构化 JSON

生成程序读取 UTF-8 JSON。顶层字段：

- `paragraphs`：正文段落，键名见示例；所有字段均应提供。
- `holdings`：持仓数组。每项包括 `name`、`cost_wan`、`value_wan`、`return_pct`、`category`、`weight_pct`。
- `indices`：指数数组。每项包括 `market`、`name_code`、`month_return_pct`、`two_month_return_pct`。
- `operations`：操作总览。每项包括 `product`、`status`、`advice`，可选 `status_value` 用于按正负着色。
- `holding_details`：逐只存量建议的完整段落数组。
- `new_product_details`：逐只调入产品的完整段落数组。
- `core_conclusion`：核心结论模块文字。
- `sources`：来源数组，每项包括 `label` 和 `url`；没有链接时为空数组。
- `document`：可选元数据，包括 `title`、`subject`、`created_utc`。

比例可使用数值或已格式化字符串；建议数值字段使用数值，由程序统一显示百分号。金额单位统一为万元。表格总计行由程序根据 `holdings` 自动生成，但正文和操作建议中的金额仍需自行核对。

正文使用的来源编号应与 `sources.label` 一致。每个具体持仓和调入产品建议应是完整自然段，并以“产品名（代码）。”开头，程序将第一个句号前的内容加粗。
